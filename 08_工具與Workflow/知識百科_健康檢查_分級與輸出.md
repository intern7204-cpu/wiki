# 知識百科 health check 分級與輸出

## 一句話定義

這一頁負責補充 [[知識百科_健康檢查流程]] 的後半段：issue 分級、標準報告格式、執行節奏，以及 raw verification queue 的操作細節。

## 核心機制

### Phase 3 — 驗證佇列（這一步才允許回查 raw）

### 核心限制

**每次 health check 結束後，若需要回查原始文件驗證，單一回合最多只讀 5 個 raw files。**

這 5 個名額只給：
1. Tier 1 新來源但疑似未整合
2. 可能推翻既有主結論的來源
3. 牽涉多頁矛盾的來源
4. 缺頁判定所需的代表性來源
5. 高影響但高不確定性的 backlog 項目

### 5-file 驗證選件規則

每回合從候選池排序：
1. Tier 1 > Tier 2 > Tier 3
2. 影響主幹頁者 > 只影響邊角頁者
3. 可一次解決多個 lint issue 者 > 只能解一個 issue 者
4. 新來源 > 舊來源
5. 已在 log 中被標成 pending 很久者，優先往前排

### 驗證回合輸出

每次只產出：
- 本回合已驗證 raw files（最多 5）
- 驗證後被確認的 issue
- 被排除的 false positives
- 延到下回合的 queue

### 建議的 issue 分級

### P0 — 結構性錯誤
- broken link
- index 條目失真
- frontmatter 缺失到無法判讀

### P1 — 知識風險高
- 新 Tier 1 結論未更新主幹頁
- 明顯矛盾但未標示
- 核心頁缺失導致知識斷鏈

### P2 — 網路品質不足
- 孤立頁面
- outbound link 不足
- 頁面過長應拆分

### P3 — backlog / ingest queue
- raw 已存在但尚未編入
- Tier 3 補充來源待整理

### 每次 health check 的標準輸出格式

1. Summary
   - total issues
   - P0 / P1 / P2 / P3 數量
   - 本回合是否有 raw 驗證

2. Structural findings
   - orphans
   - weakly linked pages
   - index/frontmatter issues

3. Knowledge findings
   - stale candidates
   - contradiction candidates
   - missing core topics

4. Backlog findings
   - raw exists but not ingested
   - 依 Tier 分類

5. Raw verification queue
   - 本回合已讀 0–5 件
   - 下一回合建議讀取 1–5 件

6. Recommended actions
   - 先修連結
   - 再補主幹頁 / 衝突標示
   - 最後處理 backlog ingest

### 執行節奏建議

### 輕量版（每週）
- 只跑 Phase 0–2
- 不一定讀 raw
- 目標：快速抓結構退化與 backlog 增長

### 深度版（雙週或每月）
- 跑 Phase 0–3
- 啟用 5-file raw verification cap
- 目標：處理 stale / contradiction / missing core topic

### 實務判準

- 若 issue 可以只靠 wiki 內部結構確認，就不要浪費 raw 驗證名額。
- 若 issue 牽涉「是否真的有新結論」或「是否真的與既有結論矛盾」，才進 raw 驗證 queue。
- 若 backlog 很大，不追求一次清空；優先讓主幹頁持續正確、可導航、可追溯。
- 每次 health check 後都要留下明確 queue，避免下次重新 triage 一遍。

## 治療原則

## 臨床決策點

- 什麼情況要治療？先看是否真的改變 pain、function、safety、participation 或訓練輸出。
- 什麼情況要轉介？遇到 red flags、診斷不確定、需要程序性介入或超出本頁可處理範圍時。
- 什麼情況不該做？當證據不足、機制不合、風險高於預期收益，或結果不會改變決策時。
