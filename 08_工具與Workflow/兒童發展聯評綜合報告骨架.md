# 兒童發展聯評綜合報告骨架

## 一句話定義

兒童發展聯評綜合報告的核心，不是把各專業意見堆在一起，而是輸出一份 **child-function + family-context + coordinated recommendation** 的整合文件。

## 核心機制

### 報告最低結構

1. 基本資料與評估專業領域
2. 壹、評估結果報告
3. 貳、評估結果與療育建議書
4. 參、病因診斷分類表

### 壹、評估結果報告要有什麼

- 主訴與就診問題
- 團隊評估總結
- 疑似 / 確定診斷
- 各功能領域摘要：
  - 知覺動作功能
  - 吞嚥 / 口腔功能
  - 口語溝通功能
  - 認知功能
  - 社會情緒功能
  - 日常生活功能
  - 環境支持
  - 家庭評估
  - 親職功能

### 貳、療育建議要有什麼

- 問題優先序
- 需轉介的專業與原因
- 家庭可立即執行的支持措施
- 教育 / 早療 / 社政資源連結
- 是否需要複評與預定時點

### 參、病因分類表的角色

- 這是 etiologic / administrative layer。
- 不能拿來取代 functional narrative 與 multidisciplinary formulation。

## 評估方式

### 實際撰寫順序

1. 先收斂各專業原始評估重點
2. 用 team language 重寫成共同 problem list
3. 把 child function、family context、resource gap 放進同一份 summary
4. 最後再填 diagnosis / classification 與追蹤安排

### 不能漏掉的欄位

- 家庭資源與限制
- 親職功能
- 環境支持
- 跨專業一致的建議與追蹤時點

## 治療原則

### 報告撰寫原則

- 先寫 function，再寫 label
- 先寫團隊整合，再寫個別專業細節
- 建議要能落地，不要只寫「持續復健」
- 需要衝突時就明示，不可默默覆寫

## 臨床決策點

### 反對論點

- 「聯評報告只要把各科結果填進格式就完成了。」

### 反駁

- 只有格式，沒有整合 summary，團隊就無法共享 formulation。
- 只有 child deficit，沒有 family / environment / parenting，療育建議通常會失去可執行性。

### 結論

- 聯評報告的真正輸出，是 **可協調、可轉介、可追蹤的 team formulation**。

## 限制與未定論

### 目前限制 / 爭議點

- 這頁是 workflow 骨架，不是 diagnosis validity 或 efficacy evidence。
- 報告完整不代表臨床判斷一定正確，仍需依 individual case quality 控制。

### frontmatter contradictions

- This workflow standardizes report structure and coordination; it does not by itself prove diagnostic validity or treatment efficacy.
- Family assessment and parenting function are required parts of the report rather than optional social background.

## 理解缺口

- 哪些聯評單位最容易漏 family / parenting narrative？
- 團隊 summary 要如何避免只是多科意見並列？

## 臨床使用版

- 若要寫聯評報告，先用這頁檢查 structure 是否完整，再回頭補 narrative quality。
- 若問題是 diagnosis 是否成立或 treatment 是否有效，這頁不是答案，需回原始評估與證據層級。
