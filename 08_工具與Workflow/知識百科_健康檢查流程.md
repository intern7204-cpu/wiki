# 知識百科 lint / health check 工作流

## 一句話定義

先用 `C:\知識百科` 的已編譯頁面做全量結構掃描，再把「真正需要回查原始文件」的問題收斂成小批次驗證；**每一回合最多回讀 5 個 `C:\原始資料` 文件**。這個 5-file cap 只適用於 health check，**不等於** [[知識百科_ingest_工作流]] 的 10-file ingest batch cap。

## 核心機制

### 核心原則

1. `C:\原始資料` 是 immutable；health check 不修改 raw layer。
2. 第一輪先查 compiled wiki，不預設重讀 raw files。
3. raw 回查只用來驗證高風險問題，不用來做大規模重新 ingest。
4. 若 backlog 很大，採「發現 → 分級 → 排隊 → 每回合最多驗證 5 件」的節奏。
5. 任何衝突都要顯式標示，不可默默覆寫既有結論。
6. health check 若需要大規模主題擴編，應轉交 [[知識百科_ingest_工作流]]，不要在 verification 回合內偷做 10 份以上來源的重新 ingest。

### 每次 health check 的固定輸入

必讀：
- `SCHEMA.md`
- `index.md`
- `log.md` 最近紀錄
- `00_總覽/`～`09_來源摘要/` 全部 `.md`

可選但不預設全文讀取：
- `C:\原始資料` 的檔名、路徑、檔案 stem、可能存在的配對 `.md`

### 工作流總覽

### Phase 0 — Orientation

1. 讀 `SCHEMA.md`，確認規則沒有變。
2. 讀 `index.md`，掌握目前已建頁面與主題空洞。
3. 讀 `log.md` 最近 20–50 行，確認最近 ingest / update / lint 焦點。

### Phase 1 — 全量結構掃描（不讀 raw 內容）

#### 1. 孤立頁面

定義：
- 無 inbound wikilink 的頁面。

檢查方式：
- 掃描所有知識頁與來源摘要頁的 `[ [ … ] ]` wikilinks。
- 建立 inbound map。
- 找出 inbound = 0 的頁面。

輸出欄位：
- page path
- 所在資料夾
- outbound link 數
- 建議補連結頁面

#### 2. 缺乏交叉連結的頁面

定義：
- outbound wikilink < 2；或
- 雖有 2 條以上，但都只連向來源摘要、沒有連向平行概念頁。

判定優先順序：
- `04_CPET/`、`05_Exercise_Physiology/`、`03_疾病與臨床主題/` 內的主題頁優先修。

輸出欄位：
- page path
- outbound count
- 可補的 cross-links 候選

#### 3. index completeness

定義：
- 實際存在的頁面未出現在 `index.md`；或
- `index.md` 內有條目但檔案不存在。

#### 4. frontmatter / 格式檢查

最低要求：
- `title`
- `created`
- `updated`
- `type`
- `domain`
- `tags`
- `sources`
- `source_tier`
- `evidence_level`
- `confidence`
- `contested`
- `contradictions`

附帶檢查：
- `type` 是否符合 schema
- `source_summary` 以外頁面是否至少有 2 個 wikilinks
- 頁面是否超過 200 行

### Phase 2 — 知識健康度掃描（仍以 wiki 為主）

#### 5. 舊結論未被新來源更新

優先看這三種訊號：
1. `09_來源摘要/` 有較新的 Tier 1 summary，但對應主題頁 `updated` 早於該 summary。
2. 主題頁的 `sources:` 未納入已存在且明顯相關的新來源摘要頁。
3. `log.md` 顯示已有 ingest，但主題頁仍保留舊 framing、未反映新 review / guideline / textbook 結論。

先標為 `stale_candidate`，不要立刻判死刑。

#### 6. 相互矛盾但未標示的頁面

先抓明顯候選：
- 同一主題頁與來源摘要頁用語相反，但 `contested: false`
- 同主題多頁對同一概念給出不同邊界、不同定義、不同臨床解讀
- 已有 `新興證據` 內容，但 frontmatter 沒有 `contested: true`
- `contradictions:` 為空，但正文已明講 conflicting findings

高風險關鍵字例：
- gold standard
- true boundary
- obsolete
- should / should not
- superiority
- reliable / unreliable
- valid / invalid
- equivalent
- replace / supersede

#### 7. 應建立但尚未建立的核心主題頁

判定來源：
1. 多篇 `09_來源摘要/` 反覆提到同一核心概念，但 `00`～`08` 沒有對應主題頁。
2. 某主題頁已承載過多不同概念，顯示應拆出獨立核心頁。
3. domain anchor 已成形，但缺少中樞頁。

目前此知識百科的優先缺頁應用以下邏輯判定：
- 若 2 篇以上來源摘要都提到某概念，優先建頁。
- 若該概念是多頁共同依賴的橋樑概念，優先建頁。
- 若缺頁導致 cross-links 只能硬連到來源摘要，也優先建頁。

#### 8. 原始來源已存在，但尚未編入知識百科

只比較 inventory，不先讀內容：
- 掃描 `C:\原始資料` 的檔名 stem
- 掃描 `09_來源摘要/` 的 stem
- 建立「raw 存在 / summary 不存在」名單

再分三類：
- A. 明顯高價值：review、textbook、UpToDate、guideline
- B. 可延後：網站、科普書
- C. 補充訊號：original article

## 臨床表現

- 本頁不是疾病頁；此處應改讀為常見使用情境、常見失敗模式與需要警覺的流程 red flags。

## 評估方式

### 本工作流的固定檢查目標

每一輪 lint / health check 至少要回答以下 6 類問題：
1. 是否存在孤立頁面（沒有 inbound links）？
2. 是否存在缺乏交叉連結的頁面（outbound links < 2，或幾乎只連向來源摘要）？
3. 是否存在舊結論未被新來源更新的頁面？
4. 是否存在相互矛盾但未標示 `contested` / `contradictions` 的頁面？
5. 是否存在應建立但尚未建立的核心主題頁？
6. 是否存在 raw source 已在 `C:\原始資料`，但尚未被編入 `09_來源摘要/` 與相關主題頁的內容？
這 6 類是 health check 的主軸；frontmatter、index、page size、log rotation 等則屬支撐性結構檢查。

## 治療原則

- 目前頁面尚未整理出 Non-pharmacologic、Pharmacologic、Injection / procedure、Rehabilitation program 的決策順序。

## 臨床決策點

- 什麼情況要治療？先看是否真的改變 pain、function、safety、participation 或訓練輸出。
- 什麼情況要轉介？遇到 red flags、診斷不確定、需要程序性介入或超出本頁可處理範圍時。
- 什麼情況不該做？當證據不足、機制不合、風險高於預期收益，或結果不會改變決策時。

## 限制與未定論

### 衝突處理規則

衝突處理已拆成獨立頁 [[知識百科_衝突處理規則]]，避免主工作流頁再次超過 200 行。

health check 在本頁只保留最短判讀原則：
- Tier 3 與 Tier 1 不一致時，先標為「需顯式標示」，不是直接判主幹頁錯。
- 多篇 Tier 3 一致挑戰舊 Tier 1 時，列為高優先 `contradiction_candidate` 或 `stale_candidate`，並進 raw verification queue 候選。
- 新版 Tier 1 已存在但主題頁未更新時，列為 `stale_candidate`，優先高於一般 backlog。

## 理解缺口

- 知識百科 lint / health check 工作流 的核心輸出是什麼？如果要教給住院醫師，最少要保留哪三個步驟？
- 哪些情況代表這個流程或總覽頁仍然不夠可執行？
- 這頁和相鄰主題頁的邊界在哪裡？
- 目前缺少明確處置順序：何時觀察、何時介入、何時轉介仍需補強。
- 目前缺少 bedside 可辨識表現：症狀、檢查發現或 red flags 仍需補強。

## 臨床使用版

- 若 知識百科 lint / health check 工作流 不能縮短查找、整理或衝突處理時間，代表流程描述仍然不夠可執行。
- 每一步都要能回答下一個實際動作是什麼，否則就只是說明文件，不是 workflow。
